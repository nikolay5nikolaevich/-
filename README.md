# Вода и молоко — новый сайт

Я сделал новый сайт для [водаимолоко.рф](https://водаимолоко.рф). Компания возит в кофейни Петербурга и области всё, что нужно для бара: молоко, сливки, воду, сиропы, стаканы, кофе и чай.

Мне хотелось, чтобы сайт ощущался как сама продукция: спокойно, чисто, немного по-утреннему. Поэтому это не длинная страница с блоками, а пять кадров. Каждый кадр — одна сцена, и каждая рассказывает свою часть истории:

1. **Кофейня утром** — с чего начинается день бариста.
2. **Молоко** — луг и корова.
3. **Вода** — источник.
4. **Всё для бара** — ассортимент карточками: можно отметить нужное и сразу добавить в заявку.
5. **Давайте дружить** — вечерняя кофейня и форма заявки.

Сцены переключаются скроллом, свайпом, стрелками или кликом. Фото внутри кадра стоят неподвижно, а движение появляется только при смене сцены: кадр мягко наезжает, а текст проявляется.

Заявка не теряется по дороге. Форма собирает имя, кофейню, телефон и выбранные позиции, копирует текст в буфер и открывает Telegram с готовым сообщением.

> Товары, цены и часть формулировок на сайте — пока заглушки. В коде они помечены `[ЗАГЛУШКА]` и `[ПРОВЕРИТЬ]`, чтобы их легко было найти и заменить на настоящие данные.

Если сайт нравится, я готов развивать его дальше. Могу наполнить его реальными товарами и ценами, оживить сцены (трава колышется, вода бежит, облака плывут) или передать проект вашей команде.

## Как это сделано

### С чего начиналось

Вся разработка шла от картинок с Pinterest. Механику переключения я взял из одного видео-референса: полноэкранные кадры, которые сменяют друг друга по скроллу. Первый экран и форма контактов тоже собраны по подборкам оттуда. Всё это лежит в папке [`референсы/`](референсы/). Сначала я собирал настроение, и только потом садился писать код.

### Claude Code и делегирование

Код писал [Claude Code](https://claude.com/claude-code). Моя роль была как у арт-директора: я ставил задачу, смотрел результат и возвращал на доработку.

Работа разделена так:

- **Claude Code** верстал сайт, писал логику переключения сцен и форму, подготавливал картинки и сам проверял сайт в браузере на разных ширинах экрана.
- **Codex CLI** генерировал картинки сцен по моим референсам. Claude Code запускал его как подрядчика и передавал промпт.
- **Я** выбирал шрифты, цвета, тексты и решал, что на сайте остаётся, а что уходит.

Чтобы каждый новый запуск помнил договорённости, я держу два файла:

- [`DESIGN.md`](DESIGN.md) — дизайн-система: сцены, тексты, цвета, шрифты, поведение на мобилке. Сначала правится этот файл, потом код.
- [`CLAUDE.md`](CLAUDE.md) — правила для агента: что можно и что нельзя, какие факты о компании настоящие, как проверять работу.

### У Claude Code нет вкуса

Это главный вывод. Claude Code быстро и аккуратно делает то, что ему сказали, но решать, красиво ли получилось, он не умеет. Его приходится постоянно поправлять:

- **Шрифт.** Я попросил поэкспериментировать со шрифтами. Агент сменил шрифт только у одного акцентного слова, а мне нужно было всё название целиком. Подходящий шрифт (Comfortaa) я нашёл сам, перебрав несколько вариантов вживую.
- **Читаемость.** Карточки ассортимента сначала были светлыми, и на светлом фоне сиропы просто терялись. Агент этого не заметил — заметил я. Карточки стали тёмным стеклом.
- **Размеры.** Заголовок «Всё для бара», визитку и навигацию пришлось просить увеличить: по умолчанию всё выходило мелким и робким.
- **Факты.** Для сцены с водой я предложил написать «возим с Байкала». Агент отказался выдумывать: на сайте компании такого нет. Здесь он прав, это я и закладывал в правила. Но о том, что выдумывать нельзя, сначала должен был сказать человек.

Итог такой: агент даёт скорость, а вкус и ответственность остаются на человеке.

### Технически

- Vite + React, обычный CSS, без UI-библиотек и фреймворков.
- Переходы между сценами сделаны только на CSS (`transform` и `opacity`), без WebGL и canvas.
- Один жест колеса или тачпада переключает ровно одну сцену. Работают свайп, клавиши, клик, точки-индикатор и ссылки в URL (`#moloko`, `#zayavka`…).
- Учитывается `prefers-reduced-motion`: если анимации в системе отключены, сцены просто плавно сменяются.
- Картинки сцен экспортируются скриптом [`scripts_prep.py`](scripts_prep.py) в WebP. Подгружаются сначала соседние сцены, остальные — после загрузки страницы.

```sh
npm install
npm run dev     # локальный сервер
npm run build   # статика в dist/
```
